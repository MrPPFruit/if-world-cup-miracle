# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Typography decision: Chinese and numeric UI text should use the local MiSans webfont from `public/assets/fonts/misans/`. MiSans is the preferred commercial-free, normal modern UI font for this prototype; avoid reverting to Luo because its paper/kai feeling is too literary for the mini-game interface.

Shared page background rule: after the home screen, all game pages should share `public/home-hero.png` as the phone-shell background image. Do not reintroduce the old CSS-only grass/sky gradient or center-line pseudo overlay; page readability should come from the existing cards and a light background veil, not from a separate artificial field layer.

Attribute page preset rule: the three named preset buttons must show an active selected state only when the current six attributes exactly match that preset. Random allocation and any custom slider edit should clear the preset highlight unless the resulting values coincidentally match a preset.

Replacement page decision: no top-right help icon; subtitle copy should be punctuation-light and meme-like. Team choices use local square SVG flag icons plus centered names, and the selected team is covered by a fixed China-team sticker asset. Keep all A-L groups visible above the CTA at a 400x865 mobile viewport.

Replacement page density decision: the selected China-team sticker should visually cover the full team pill, not sit as a small label inside it. The group table should read as a light white information surface without a visible outer border, and it should extend close to the bottom CTA so the middle area does not feel empty.
Replacement sticker rule: the China-team replacement sticker should look like a physical paper sticker pasted on top of the team pill. It may deliberately exceed the team pill boundary and must not be clipped by the pill border.

Transition page decision: match the confirmed reference as a clean text-commentary loading page. Keep the page to a compact top title, one bold incident headline, a large white feed card, a polished `小组赛剧本正在生成` status card at the top of that feed card, multiple humorous pure-text lines, and a fixed acceleration button in the grass-gradient area. The message feed is a top-in queue: the newest line appears on the first row, older lines are pushed downward, and the bottom lines fade only through a gradient mask. Time, team names, and scores should be visibly highlighted in the flow copy. Do not use countdowns, progress bars, icons, auto-scroll-to-bottom behavior, extra decorative animations, or step labels.

Transition timing decision: use a 30s transition with one new feed line about every 1.7s. Reveal all currently available transition commentary lines, then leave roughly 3s of quiet stop time before moving to the group-results screen. The acceleration button must not skip directly; it changes subsequent line reveal cadence to 0.5s, then still leaves the same quiet stop before the handoff.

Transition semantic color decision: in long commentary flows, keep time and score as capsule highlights, but separate entity colors by type: team names use blue text, player names use warm orange, and meaningful system/event words such as VAR or referee use purple. Do not highlight joke nouns like comments or calculator; they should stay as normal text so the feed does not become noisy.

Transition CTA decision: the acceleration button should use the same red `primary-button` bottom CTA system as the home, attribute, replacement, group, knockout, and result pages. Keep only route-specific positioning in transition CSS; do not reintroduce a separate pale/green capsule style for this action.

Knockout advancement board decision: do not use the full 32-team zoom tree on the match-result page. It is too small for the 400x865 mobile viewport and competes with the result and report cards. Use a readable advancement-seat board instead: after 32强 show all 16 advanced teams in flag/name cards, then automatically shrink to 8强、半决赛、决赛席位 as the user advances. Highlight 中国队 in red and the next opponent in blue. Keep this as dynamic DOM, not a flat image.
Knockout advancement board priority: the advancement-seat board is secondary information. Keep it compact, about one third shorter than the previous large board, and give the reclaimed vertical space to the match report. The match report is the primary storytelling surface on knockout result screens.
Knockout advancement board readability rule: do not compress 16 advanced teams into an 8-column layout because country names collapse into single characters. Use a 4-column by 4-row layout for the 16-team state, remove the separate footer helper copy, and keep each card's flag plus country name readable within the compact board.
Knockout podium rule: after the final match is complete, do not show the normal advancement-seat grid. Show a custom podium board with champion, runner-up, and third-place teams. The champion should be visually dominant in the center, with runner-up and third-place teams shown as secondary side cards.
Knockout final-duel rule: when the semifinal is complete and only the two finalists remain, do not show the normal advancement-seat grid. Use a dedicated final-duel board with two large team cards and a center `VS / 决赛` badge so the `决赛席位` state fills the board and reads as a matchup, not a sparse list.

Knockout page layout decision: keep the result card, match-report card, advancement-seat board, and shared red CTA all visible in one 400x865 viewport. The bottom board must sit clearly above the CTA; do not let the button overlap or cover board content. Non-commentary helper copy on this page should avoid punctuation; match-report lines may keep punctuation because they are longer broadcast-style text.
Knockout page polish rule: the top-right help icon is not useful on knockout screens, so keep only the music button. Maintain an 8px rhythm between the result card, match-report card, advancement board, and CTA. The match report should contain enough rows to feel like a real broadcast, while the final whistle row should be a lighter status strip with punctuation-free copy.
Knockout result card rule: keep a visible internal bottom safe area below the helper copy. Do not put the bottom helper copy inside a capsule because the result card already has enough pill-shaped elements. Use plain centered text with minimal divider decoration instead. If the page is vertically tight, reduce the score block height before reducing this bottom padding.
Knockout report semantic rule: match-report copy should reuse the transition feed's semantic highlight system. Time uses blue capsules, team names use blue text, player names use warm orange, system/event labels such as VAR/referee/set pieces use purple, and scores use red capsules.
Knockout report broadcast rule: the match report should reveal like a short broadcast feed, one existing report line at a time from top to bottom with no extra generated lines. While the report is still revealing, the bottom CTA reads `比赛进行中` and is not actionable; after the final report line appears, it switches back to the round's normal next-step CTA such as `进入 16 强 梦继续做`.
Knockout reveal rule: the result card score should follow the currently revealed report lines, not jump directly to the final score. Every goal in the final match score must have a matching report line. Advancement status text, helper copy, and advancement-seat boards appear only after the final report line/whistle; before that, show a pending seat state. For 16-team and 8-team advancement boards, align team cards left for scanability and animate seats in after the match is complete.

Settlement page decision: championship and failure results share one settlement-page system. Keep the top hero, miracle path, attribute radar, QR/link share panel, save button, and restart button in the same hierarchy as `final-reference.png`. The failure state should use the same layout with calmer gray-blue emphasis and route `?screen=failure`; do not create a separate full-page share screen.

Settlement page defeated-mascot rule: the championship hero left visual is now a defeated-opponent character slot, not the World Cup trophy. Use colorful two-head chibi football mascots with national-team kits, comedic defeated poses, and transparent PNG cutouts; the confirmed Argentina baseline is the seated number-10 captain-style mascot hugging a ball from `public/assets/characters/argentina-defeated-10.png`. Keep the character readable in the compact left hero slot and avoid official logos or exact crest details.
Character asset rule: use `docs/character-assets.md` as the source of truth for defeated national-team mascot generation. Generate and review assets in batches of 10 following group-stage order. New assets start as pending files under `public/assets/characters/pending/` and must match the 442x604 transparent PNG canvas, existing UI visual scale, national-team World Cup kit style, and appropriate player/squad appearance and skin tone. Expressions, poses, and props must be deliberately varied and meme-like; avoid repeating the same sitting/crying/hugging-ball formula across a batch. Each batch of 10 may contain at most 2 sitting or half-lying low-silhouette poses; prefer standing, hanging, falling, being crushed, tangled, stuck in props, or bounced mid-motion. Pending transparent PNGs must be checked on a dark background and cannot retain visible green/red/magenta chroma-key background blocks, white/yellow internal background fill, or edge residue; inspect enclosed holes such as goal-net gaps carefully while preserving legitimate white details like footballs, eye whites, kit areas, paper props, and net strings. Brazil must use the Neymar reference direction because it is more recognizable for the target Chinese audience. Player references must be from this World Cup's participating/selected national-team context; do not use retired legends or players left out of this World Cup even if they are more famous domestically.
Settlement page top-bar rule: championship and failure settlement pages keep only the music button on the top right. Do not show a top-right help icon on settlement screens.
Settlement page path/radar rule: keep the miracle path as dynamic DOM rather than a flat image, because replacement team, scores, and failure/champion state change. The left path should read as a red timeline with icon nodes, and the final match row should be a larger highlighted result strip. The settlement radar must reuse the attribute-page six-axis radar logic with full labels and 0-10 scale, only resized for the smaller card. Maintain visible 10px-class spacing between path, bottom panels, share controls, borders, and the bottom action buttons. The path title should be visually centered to the full path panel, not the padded content column, and all timeline nodes should share one vertical axis with enough left safe inset so icon nodes do not visually touch the panel border or the path-row border. The mini radar chart and labels should be visually centered inside the `国足属性` card.
Settlement page hero rule: championship hero uses the left side for the China championship copy and China flag, and the right side for the defeated-opponent character. Treat title, copy, status pill, flag, and character as one integrated hero composition. Keep hero-specific feedback scoped to the hero unless the user explicitly calls out another section.
Settlement page hero tone rule: championship hero should feel like a loud victory bulletin, not a neutral information card. Use a large dominant title, the copy `中国队历史首次夺得世界杯冠军`, stronger red-gold emphasis, and a smaller right-side defeated character contained inside the hero frame.
Settlement page hero flag rule: the China flag inside the championship title should stay prominent at 38px by 27.1px so it reads as part of the main headline, not a small label.
Settlement page final-row rule: the miracle path final match row must fully contain the opponent name, align its outer border with the ordinary path rows so it does not touch the larger final trophy node, keep safe space from the outer panel border, avoid the decorative crown in the top-right corner, and keep the larger final trophy node centered on the same vertical timeline axis as the earlier round nodes.
Settlement path containment rule: long replacement-team and opponent names in the miracle path must be contained with a shrinkable text span or ellipsis. Do not allow path text to push through the row border or disturb the left red timeline axis. Bottom save/restart buttons must keep a visible safe gap from the phone-shell bottom and keep their labels on one line.

Group result page decision: implement the confirmed `group-result-reference.png` as the source of truth. Keep the whole page visible at a 400x865 mobile viewport with no scroll and no CTA overlap. Use the top result card, F-group standings table, China three-match summary, compact other-group overview, square SVG flags, and the shared red bottom CTA.

Group result overview rule: the group-result page uses `晋级队伍速览`, not `其他小组速览`. Show 12 group summaries as a 3-column by 4-row grid when China's group must be included for balance. Each pill only contains group id and the two advanced teams; do not show a separate `晋级` label. Keep the hero footer and China three-match footer copy punctuation-free.

Group result hero rule: keep the result card background neutral white to very light blue; do not use warm yellow glows behind the trophy. The group result trophy must use the local high-quality World Cup trophy cutout (`public/assets/worldcup-trophy-cutout.png`) rather than the separate simplified `group-trophy.svg`, because the SVG reads as the wrong trophy style in the compact hero card.
Group result hero asset candidates: China survival mascot replacements for the left trophy slot live in `public/assets/group-result/china-group-survival-01.png` through `china-group-survival-10.png`. They are transparent `143 x 285` PNGs matching `worldcup-trophy-cutout.png`, so they can directly replace the trophy `src` while keeping the existing `.group-trophy` `76 x 122px` layout. The intended tone is funny, meme-like, and slightly unreachable: China has barely advanced and survived. Assets `01` through `04` are trophy-desire variants; assets `05` through `10` avoid the World Cup trophy and focus on group qualification celebration, such as calculator rescue, crossing the line, being tossed up, escaping the group-stage pit, hugging a blank qualification ticket, and flying on a paper airplane.
Group result standings rule: the China-row `压线活了` badge should live inline inside the team-name cell, not as an absolute corner badge near the points column. The badge must never cover the score/points columns at 400x865.
Group result failure rule: when China does not advance from the group, the group-result page must not reuse advancement copy. The China standings badge should read as an exit state such as `小组出局`, the primary CTA should route/copy as settlement review such as `查看本局结算`, and no visible copy should imply entering the 32-team knockout.

Settlement failure visual rule: the failure settlement hero should be a calm gray-blue variant, not the red-gold champion hero with a white copy overlay. Keep `.final-hero-copy` transparent in failure state so it does not create a strange block over the hero background. Failure bottom actions must sit with a clearly visible safe gap above the phone-shell bottom border and keep labels on one line.

Game simulation decision: replace the current UI-demo hardcoded tournament with a pure frontend simulation engine. The engine owns team data, FIFA ranking snapshot metadata, group fixtures, outcome gating, match scoring, event generation, path rows, advancement boards, and settlement payloads; React screens should render the generated result rather than define tournament truth inline.
Game simulation luck rule: the five non-luck attributes decide football content and event flavor. High defense yields more bunker, keeper, clearance, and low-score events; high attack yields more shots and finishing events; high midfield yields buildup and control events; high stamina yields late-game and extra-time events; high tactics yields set-piece, strange formation, and strong-team counter events. Luck controls positive miracle probability and commentary exaggeration only; higher luck allows more absurd accidents, VAR favors, posts, own goals, and meme-like turns.
Game simulation realism rule: team strength must be based on a frozen FIFA men's ranking snapshot plus game balancing ratings. Ranking and points are source data; `baseRating` is the game value used by scoring. Better ranked teams should usually be stronger across large samples, ranking gaps should widen expected score difference, and controlled upsets must remain possible.
Zero-luck deterministic rule: `luck = 0` means deterministic results for the same attributes and replacement team. Zero-luck champion routes are hidden hardcore routes, not random miracles. The primary hidden build is exactly `attack=7, defense=7, midfield=6, stamina=5, tactics=5, luck=0`. One required route is replacing Netherlands in F1, preserving Japan as a real team, and ending with China defeating Japan in the final. Additional zero-luck champion routes may exist, but they must be explicit table entries rather than probabilistic rescue.
Zero-luck probability rule: because exact hidden builds and exact replacement teams make the true all-configuration rate far below 3%, treat roughly 3% as the target success rate for guided zero-luck hardcore attempts, not for random 30-point configurations across all 48 teams.
Settlement character runtime rule: when China wins the championship, the settlement hero character must use the final opponent defeated by China, via `getSettlementCharacterAsset({ result: "champion", defeatedOpponentCode, defeatedOpponentName })`. When China fails, the settlement page must use one of the five China defeated variants, preferably chosen by failure reason or stable failure seed, not an opponent image.

Deployment decision: the production domain is `https://game.ppserver.xyz`. The deployment chain is Cloudflare DNS to Tencent Cloud CDN outside mainland China to Tencent Cloud COS Hong Kong Bucket static website. Keep `game.ppserver.xyz` as a Cloudflare DNS-only gray-cloud CNAME to `game.ppserver.xyz.cdn.dnsv1.com`; do not enable orange-cloud proxy for this record.
Deployment static-site rule: this project must remain a low-cost pure frontend static site. Do not add servers, databases, login systems, cloud saves, long-term persistence, paid features, rankings, backend APIs, or secrets in frontend code. Refreshing the page may reset the game to the start. Build output must be `dist/index.html`, `dist/assets/`, and `dist/__track/`, never `dist/dist/index.html`.
Deployment security rule: production uploads must contain only built `dist/` contents. Do not upload `src/`, `.env`, `.env.local`, `node_modules/`, design sources, private files, Tencent credentials, OpenAI keys, API keys, or admin passwords. Vite production sourcemaps must stay disabled, `dist/assets/` must contain no `.map` files, and production code should avoid stray `console.log` and `debugger`.
Deployment telemetry rule: first version should use CDN logs only. A frontend `track(eventName, data)` helper may request `/__track/pixel.gif?...` with an anonymous `sessionStorage` session id; this is allowed only for per-session telemetry and must not store game progress or sensitive data. Required first-version events are `page_view`, `game_start`, `attribute_submit`, `team_selected`, `group_stage_result`, `knockout_result`, `final_result`, `champion`, `failed`, `restart`, and `share_click`. `public/__track/pixel.gif` must exist so the build can serve `dist/__track/pixel.gif`.

Dynamic commentary tone rule: generated copy should be varied, meme-like, and occasionally culturally referential, but jokes must come from match facts, football context, Chinese internet phrasing, or the game's alternate-universe setup. Do not use vulgar, hostile, body-shaming, protected-class, national/ethnic attack, or player-humiliation humor. Star-player references must stay within the static national-team player profile system and match the player's team and position.
